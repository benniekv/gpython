## Spec

|---|---|---|

| `parser/` | Hand-written lexer plus a goyacc grammar (`grammar.y`, `y.go`). | 3 files |
| `ast/` | AST node types (`ast.go`), walker, dumper. `Python.asdl` is the source of truth. | 4 files |
| `symtable/` | Symbol table construction and scope analysis. | 3 files |
| `compile/` | AST to bytecode compiler, instruction set (`instructions.go`). | 4 files |
| `vm/` | The virtual machine, opcodes, evaluator. `vm/benchmarks/` holds benchmarks. | 8 files |
| `stdlib/` | Python modules: `builtin`, `math`, `sys`, `time`, `os`, `string`, `array`, `binascii`, `glob`, `marshal`, `tempfile`. | 11 modules |
| `repl/` | Interactive mode: `repl/cli` for the terminal REPL, `repl/web` for the web REPL. | 4 files |
| `pytest/` | Test harness that runs Python test files and compares against golden output. | 2 files |
| `importlib/` | Import machinery. A frozen blob of CPython 3.4's `_bootstrap.py`. | 1 file |
| `ci/` | `run-tests.go`, the CI test driver. | 1 file |
| `examples/` | `embedding/` and `multi-context/` show how to host gpython in a Go program. | 2 files |
| `specs/` | The specification set. Read `specs/README.md` for the index. | - |

### The package dependency graph

Measured from the non-test imports:

```
py            (base: no internal package imports)
ast   -> py
parser-> py
symtable -> ast, parser, py
vm     -> py
compile-> ast, parser, symtable, py, vm
stdlib -> compile, py
repl   -> py, stdlib, vm
```

**`py` is the base.** It imports no other internal package. A new import that
points the other way, for example `py` importing `compile`, is a design
error. `compile` and `stdlib` are the two places where a cycle is most
tempting.

### The four code generators

| Generator | `go:generate` directive | Input | Output | Tool |
|---|---|---|---|---|
| Arithmetic | `py/py.go:9` `go run gen.go` | a table in `py/gen.go` | `py/arithmetic.go` | none, just `go run` |
| Grammar | `parser/parser.go:10` | `parser/grammar.y` | `parser/y.go`, `parser/y.output` | `goyacc` |
| Stringer | `symtable/symtable.go:27` | `symtable/symtable.go` | `symtable/stringer.go` | `stringer` |
| Stringer | `vm/vm.go:12` | `vm/vm.go`, `vm/opcodes.go` | `vm/stringer.go` | `stringer` |
| ASDL | none | `ast/Python.asdl` | `ast/Python-ast.go` | `ast/asdl_go.py` |

**The `stringer` invocation must run from inside the package directory.**
The directive says `stringer -type=Scope,BlockType -output stringer.go`,
which fails with `no packages matching .` from the repository root.

**The generators do not emit the licence header**, but every tracked
generated file carries it. The Makefile's `_add-license` target prepends it.

**Details and the exact regeneration diffs:**
`specs/02-language-upgrade/06-porting-and-build-system.md`.

### The testing conventions in full

**Go unit tests.** Standard `testing` package, `*_test.go` next to the code.
Table-driven where several cases exist.

**Python test files.** A `.py` file under a `tests/` directory next to the
package. The Go test file calls `pytest.RunTests(t, "tests")` to run them.

```
py/tests/string.py              -> run by py/py_test.go
stdlib/builtin/tests/builtin.py -> run by stdlib/builtin/builtin_test.go
vm/tests/*.py                   -> run by vm/vm_test.go
```

Adding a Python test means dropping the `.py` file into the right `tests/`
directory. No Go change is needed.

**The golden file mechanism.** The harness compares program output against
golden files in `testdata/`. There are two kinds, and they are different:

| Kind | Files | Generated by |
|---|---|---|
| Stdlib module goldens | `stdlib/*/testdata/test_golden.txt` | gpython itself, with `-regen` |
| Compiler goldens | `compile/compile_data_test.go`, `symtable/symtable_data_test.go`, `parser/grammar_data_test.go` | **CPython**, with the Python scripts |

**The compiler goldens are the test oracle.** They are generated from
CPython's own `compile()`, `symtable.symtable()` and `ast.dump()`, so they
state what CPython does, not what gpython does.

**Never regenerate the compiler goldens from gpython's own output with
`-regen`.** That would rewrite the oracle to match the implementation and
hide the difference. Use `make generate-testdata`, which runs the Python
scripts against a CPython interpreter.

**The `-regen` flag is only for a stdlib module's `testdata/test_golden.txt`**,
and only when the module's correct output changed on purpose.

**The Python scripts need the right CPython version:**

| Script | Needs |
|---|---|
| `compile/make_compile_test.py` | CPython 3.4 to reproduce the tracked data; CPython 3.15 to produce the target data |
| `symtable/make_symtable_test.py` | CPython 3.4, plus a rebuilt `readsymtab` C extension for 3.15 |
| `parser/make_grammar_test.py` | CPython 3.4, or CPython 3.15 for the target |

The `symtable` script has a `ctypes` fallback that reads CPython's
`PySTEntryObject` **by offset**. That layout changed between 3.4 and 3.15,
so the `readsymtab` extension must be rebuilt before the script works on
3.15.

### The code conventions in full

**The licence header.** Every Go file starts with exactly two comment lines:

```go
// Copyright 2018 The go-python Authors.  All rights reserved.
// Use of this source code is governed by a BSD-style
// license that can be found in the LICENSE file.
```

Note the **two spaces** after the period in "Authors.  All rights
reserved." That is the GNU style, not Go's usual one space. Reproduce it
exactly.

**The year is the year the file was created**, not the current year. Do not
bump the year on a file you only edit.

**The `I__dunder__` naming convention.** gpython maps Python's dunder
methods to Go interface methods named `I__<name>__`. 87 distinct dunder
methods are implemented this way. The `I__` prefix avoids colliding with
Go's own keywords and makes the mapping explicit at the call site.

**Error text is an argument, never a format string.** Go 1.27's vet
enforces this:

```go
// Wrong: the error message is the format string.
return nil, ExceptionNewf(OSError, err.Error())

// Right: the error message is an argument.
return nil, ExceptionNewf(OSError, "%s", err.Error())
```

**The comment style.** Exported identifiers carry doc comments that start
with the identifier name. 92% of exported functions have one. A comment
above a declaration starts with a capital letter and reads as a sentence.
It does not end with a period when it is a fragment describing an
identifier.

**The panic-dominant error handling.** gpython panics for programmer errors
and returns errors for expected failures. 105 panics against 16
`fmt.Errorf` calls. The exception is the test harness, which returns
`error` values because `testing.T` needs the error reported rather than the
process killed.

**Full detail with the measurements:**
`specs/02-language-upgrade/04-code-style-and-testing.md`.

After the Go 1.27 upgrade, all of these are clean:

| Check | Command | State |
|---|---|---|
| Build | `go build ./...` | clean |
| Vet | `go vet ./...` | clean, 0 findings |
| Test | `go test -tags=ci ./...` | 19 packages pass |
| Format | `gofmt -l -s .` | no output |
| Static analysis | `bin/tools/staticcheck ./...` | 0 findings |
| wasm | `GOOS=js GOARCH=wasm go build .` | builds, but on an archived dependency |

**Before the Go 1.27 upgrade**, vet reported 14 findings and staticcheck
reported one. All are fixed. The details are in
`specs/02-language-upgrade/06-porting-and-build-system.md`.

## Verification

**1. Confirm the layout table matches the tree.**

```bash
ls py/ ast/ parser/ symtable/ compile/ vm/ stdlib/ repl/ pytest/ importlib/ ci/
```

Expect the directories listed in the table.

**2. Confirm the dependency graph.**

```bash
go list -deps ./... | grep go-python/gpython | sort -u
```

**3. Confirm the generators.**

```bash
grep -rn 'go:generate' --include=*.go . | grep -v _test
```

Expect four directives.

**4. Confirm the golden files are tracked and the stdlib goldens are not
mixed in.**

```bash
git ls-files | grep -E 'data_test\.go|test_golden\.txt'
```

Expect three `*_data_test.go` and seven `test_golden.txt`.

**5. Confirm the checks are clean.**

```bash
make check
```

Expect every step to pass.
